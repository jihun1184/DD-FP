## 2. Supported hardware and software

- **Used for the reported measurements:** NVIDIA RTX 4090 (24,564 MiB), driver 595.99.02 (whole-grid verification and stage E6; stage E1: 580.178.04), CUDA 13.2, CuPy 14.2.0, NumPy 2.2.6, Python 3.10.21–3.10.22, Intel i9-14900KF. The retained GPU-comparison environment record `cmpb/data/g5_environment.json` identifies Linux 7.0.0-38-generic x86_64 (glibc 2.43) for that run; this is not inferred to describe every measurement.
- **CPU-only parts** (sequential FP, CPU DWC checker, smoke tests, theorem tests, CPU self-checks): any platform with Python ≥ 3.9 and the packages in `requirements.txt`; tested on Python 3.13 (Linux).
- **Not evaluated:** other GPUs, other CUDA/CuPy versions, other operating systems, multi-GPU execution. The code uses one device; slabs are solved in sequence.

## 3. Installation

```bash
git clone https://github.com/jihun1184/DD-FP.git && cd DD-FP && git checkout v1.0.1
python -m pip install -r requirements.txt
python -m pip install cupy-cudaXXx        # GPU only; use the CuPy build for your CUDA toolkit
```

Keep newline characters unchanged (`.gitattributes` is provided). With CRLF conversion the SHA-256 of the frozen kernel changes and `load_canonical()` refuses to load it.

## 4. Minimal commands

```bash
python -m pytest test/test_smoke.py -q                      # CPU; add --run-gpu on a CUDA machine
python cmpb/theorem_tests/r0_verify.py checker              # proof-step consistency tests (CPU); modes: checker | local | random | exhaustive | mutants

python -I cmpb/evaluation/e_runtime_r7_runner/e2/gpu_parity/run_gpu_parity.py --selfcheck --no-pause   # CPU self-check
```

(The first three commands run from the repository root; the theorem tests import `r0lib` from their own directory.)

GPU-FP (K = 1), DD-FP direct assembly and IBI: see the snippet in the README. Argument conventions of `run_ibi_v10(vol_u8, K, delta, max_rounds, l_inf, verbose)`: `K` slabs along the last axis, `delta` halo width (the analysed setting is δ = 1), `max_rounds=0` direct assembly, `max_rounds=r` at most r seeded rounds.

## 5. Inputs and outputs

- **Input volume.** 3-D `uint8` array of shape (W, H, D), integer values 0–255. For BraTS the evaluation loads the FLAIR NIfTI and applies percentile scaling to 0–255 (not timed). Theorem 3.1 assumes integer-valued input.
- **Expanded lattice.** Output shape (2W−1, 2H−1, 2D−1); BraTS volumes (240×240×155) give 479×479×309 = 70,897,269 cells. Odd-index cells hold the original voxels; the other cells hold interpolated values.
- **Interval map and frame.** `build_ispan_*` returns lower and upper bound arrays of shape (2W+1, 2H+1, 2D+1) including a one-cell frame, plus `l_inf` (start level, 0 in the evaluated configuration). The front-propagation functions return an array of the same padded shape; the interior is `[1:-1, 1:-1, 1:-1]`.
- **GPU-FP (K = 1)** returns one float32 expanded array. **`run_ibi_v10`** returns a dictionary with `u_dd` (expanded array on the host), `boundary_z_orig` (slab boundaries), `R_star` (rounds used; 0 for direct assembly) and `t_total_s`.
- **DWC check.** `verify_dwc_gpu(u)` returns `dwc_ok`, `violations`, `nan_skipped`, `total_blocks`, `violation_rate`; `verify_dwc(original, u)` (CPU) returns `n_violations`, `max_abs_error`, `violation_rate`. The whole-grid check covers face blocks (xy, xz, yz) and cube blocks.
- **Evaluation stages** write JSON/JSONL rows, stage metadata and SHA-256 manifests into their result folders.

## 7. Reproducibility limitations

1. **No CUDA execution in the release preparation.** All GPU claims rest on the authors' earlier runs. The CPU self-checks and shim tests test plumbing and decision logic, not CUDA correctness.
2. **Only small stored records are in this repository** (`cmpb/data/`): per-image DRIVE/CREMI-2D record, timing, memory and exploratory-profile records. The saved output arrays of the whole-grid verification, the qualitative arrays, the BraTS topology arrays, the raw rows of the 77-crop Min/Max operator comparison (record E1) and the datasets are not included; the held-out slice reconstruction metrics are included (`cmpb/data/reconstruction/`) and re-aggregate with `python3 -I cmpb/manuscript_tools/recompute_reconstruction.py cmpb/data`; the tables and figures that depend on them cannot be regenerated here (`FIGURE_TABLE_REPRODUCIBILITY.md`).
3. **Producers not located for some evidence.** The seam-layer survey (tier F) and the Min/Max operator comparison (tier O) have no producing script in this repository; the producer of tier V, and the producers of the CREMI-3D and 33-subject BraTS aggregates of tier C, are probable but not confirmed (see the mapping).
4. **H-GPU is not proved.** That the CUDA code realizes P1–P5 is supported by code inspection and finite observations only. Theorem 3.1 is a conditional result, not machine-verified.
5. **Hardware-specific timing.** Runtimes are from one RTX 4090 system; the sequential reference is an unoptimized single-thread Python implementation, so the 8.05× ratio is not a comparison with optimized CPU code. 25 of 182 controlled-benchmark records carry a GPU-contention flag and were not excluded.
6. **Memory results.** Reserved-peak ratios include allocator effects; the effective sample size of the memory benchmark is about one; the single-device implementation retains full-volume arrays.
7. **Earlier sequential reference.** The `cpu_fp.py` of commit `8fdfe62` gives different output on non-cubic 3-D volumes (see [`LEGACY_NOTICE.md`](LEGACY_NOTICE.md)); use the released version. The version behind each sequential-FP result is documented in [`CPU_FP_PROVENANCE.md`](CPU_FP_PROVENANCE.md); the CREMI-3D and 33-subject BraTS aggregates are not tied to a recorded version.
8. **Hash-enforced files.** The evaluated source tree is frozen. Documentation fixes inside those files (see [`LEGACY_NOTICE.md`](LEGACY_NOTICE.md)) require new hashes and a new evaluation record.
9. **Environment differences.** The CPU checks were run on Python 3.13; the evaluation used Python 3.10. The earlier README listed a different environment (RTX 3080 Ti, CuPy 13.6.0); those timings are not used in the manuscript.
10. **AI-assisted development.** Parts of the code, the experimental protocols and the proof of Theorem 3.1 were developed with AI assistance, as disclosed in the manuscript.
11. **Data terms.** BraTS 2021, DRIVE and CREMI are used under their own licences and are not redistributed.

## 8. Final release verification (2026-10-28)

Windows / Python 3.12.14: 65 CPU smoke tests passed, 12 CUDA tests skipped; README CPU example and compileall passed. Pyflakes 4.0.3 reported 150 diagnostics on unchanged sources (including the quoted `NoReturn` annotation); the earlier tool run recorded 149. Frozen files were preserved. Root and CMPB manifests and the six evaluated file hashes were checked. Earlier checks in §1 remain historical records, not reruns. No CUDA execution, new scientific experiment or proof test campaign was performed. See RELEASE_NOTES.md for scope.
